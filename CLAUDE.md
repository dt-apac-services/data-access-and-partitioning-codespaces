## Project Overview

This is a hands-on training lab for Dynatrace 3rd-Generation platform features. It teaches data access control (IAM), data partitioning, cost allocation, metadata enrichment, and Kubernetes integration through a simulated customer engagement scenario using the "Easytrade" application.

The lab runs as a VS Code devcontainer (GitHub Codespaces or local) that provisions a Kind Kubernetes cluster with Dynatrace monitoring and sample applications.

## Build and Development Commands

### Devcontainer Build (from `.devcontainer/` directory)
```bash
make start              # Start container (builds if needed)
make build              # Build image with cache
make build-nocache      # Build image without cache
make buildx             # Multi-architecture build (AMD64/ARM64)
make integration        # Run integration tests
```

### Documentation
```bash
pip install -r docs/requirements/requirements-mkdocs.txt
mkdocs build            # Build documentation
mkdocs serve            # Serve documentation locally
mkdocs gh-deploy        # Deploy to GitHub Pages
```

### Monaco Deployment (Dynatrace config-as-code)
```bash
/workspaces/data-access-and-partitioning-codespaces && .devcontainer/monaco.sh
```

### Kubernetes Cluster Management
```bash
kind delete cluster                              # Delete cluster
docker volume rm $(docker volume ls -q | grep kind)  # Clean up volumes
```

## Architecture

### Container Lifecycle
1. **`devcontainer.json`** - Defines the container config, secrets, and port forwarding (30100 for app UI)
2. **`post-create.sh`** - Main provisioning: validates inputs, starts Kind cluster, deploys Dynatrace Operator, deploys sample apps
3. **`post-start.sh`** - Runs on container restart: exposes MkDocs documentation

### Key Directories
- **`.devcontainer/util/`** - Shell framework with reusable functions
  - `functions.sh` - Core utility functions (logging, waiting, deployments)
  - `variables.sh` - Version numbers and configuration variables
  - `validate_inputs.sh` - Token/tenant validation and OAuth setup
- **`.devcontainer/yaml/`** - Kubernetes manifests for DynaKube deployment modes
- **`.devcontainer/apps/`** - Sample applications (easytrade, todo-app, hipstershop, astroshop, ai-travel-advisor)
- **`docs/`** - MkDocs documentation with 10+ lab modules

### Required Secrets
- `DT_TENANT_3RDGEN` - Dynatrace tenant ID (e.g., `abc123` for `abc123.live.apps.dynatrace.com`)
- `DT_TOKEN` - Access token with "Write API tokens" scope
- `CLIENT_SECRET` - OAuth client secret with required permissions

### Environment Variables (auto-generated by validation)
- `DT_TENANT`, `DT_INGEST_TOKEN`, `DT_OPERATOR_TOKEN`, `MONACO_TOKEN`, `CLIENT_ID`, `SSO_ENDPOINT`

## CI/CD

- **Pull Requests to `main`**: Runs integration tests via `.devcontainer/test/integration.sh`
- **Push to `main` or `docs/*`**: Deploys MkDocs documentation to GitHub Pages

## Local Development Setup

For local development (not Codespaces), modify `devcontainer.json` runArgs to include env file:
```json
"runArgs": ["--init", "--privileged", "--network=host", "--env-file", ".devcontainer/runlocal/.env"]
```

Create `.devcontainer/runlocal/.env` with required secrets. Do not commit this change.
